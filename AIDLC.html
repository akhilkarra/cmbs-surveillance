CMBS surveillance · how it's built

An AI writes and ships the code. Automatic checks gate every change; a person decides what it must do.

The app turns public SEC filings on commercial mortgage loans into a monitoring panel. Claude, an AI assistant, wrote it.

  • AIThe maker: drafts, builds, ships.
  • Person (me)Decides the design, signs off each requirement.
  • AutomaticChecks that block a bad change, like a limit blocks a trade.
Stages a change must clear

e.g. fix › fields a servicer comment never mentions now read "not stated" instead of going to manual review

  1. The AI asks; a person decides.

  2. Drafts don't count until signed off.

  3. The AI is blocked from signing off or editing signed-off requirements.

  4. AI answers are recorded and replayed, so tests repeat.

    Proved: scheduled balances roll forward (loss months excepted), delinquency buckets sum to the pool, WAC stays in the note-rate range, each comment reading has one outcome. The Python is tested against the proofs, not proved.

  5. Catches errors, leaked passwords and confidential names in every saved version.

  6. It sees only the code and requirements. Findings get fixed with tests; review texts weren't kept.

  7. Every test and proof reruns on a clean machine.

  8. The AI merges its own changes; a script confirms it's the right one.

  9. Nightly, the code is deliberately broken to see if tests notice (currently failing).

The intended order. So far, sign-off came after the build (see gaps). Tap for details.

Nine stages, each with a check.

Why it matters

AI code looks right even when it is wrong.

  • The risk: a silently wrong number is worse than a crash.
  • The stance: assume the AI errs; a person or an automatic check checks it.
  • The numbers are checked too: balances must roll forward, and the 10-D and servicer text must tie to the loan tape. A break raises a flag; nothing is silently fixed.

Evidence

14 AI mistakes caught. Only 2 by automatic checks.

The rest: 6 by the AI rechecking its own work, 4 by a person, 1 by a second AI, 1 by the first live run of the AI model.

Mistake log
  1. ✓Caught by the first live model run. The AI's rule sent unmentioned fields to manual review: 13 of 30, not 3. Fixed; the real answers are now tests.
  2. ✓Caught by the automatic checks. A newer Python than the AI assumed broke a dependency. Now pinned.
  3. ✓Caught by a second AI. A research AI called a deal publicly registered; no 10-D or loan tape exists under its name.

The catch

What it doesn't prove yet.

  • Sign-off came late. All but one requirement was signed off after it was built.
  • The AI holds admin keys. With the owner's access, it could switch off the checks.
  • Accuracy is barely measured. Checked on five servicer comments, only two from real filings.
  • Sign-off can be faked. Nothing ties it to a person.
  • The nightly break-the-code run is failing. Every night since 31 October.

Claude skills

Skills: reusable playbooks for the AI.

  • While building: a questioning skill ran the design debate; the AI vendor's skill reviewed the model calls.
  • At run time: analysts type /cmbs-refresh to pull new filings or /cmbs-ask to ask about a loan; answers cite the SEC filing.
  • The limit: each is pre-approved to run only the app's commands; anything else needs the user's OK.
