CMBS surveillance · how it's built

An AI writes and ships the code. Automatic checks gate every change; a person decides what it must do.

The app turns public SEC filings on commercial mortgage loans into a monitoring panel. Claude, an AI assistant, wrote it.

  • AIThe maker: drafts, builds, ships.
  • Person (me)Decides the design, signs off each requirement.
  • AutomaticChecks that block a bad change, like a limit blocks a trade.
Stages a change must clear

e.g. fix › fields a servicer comment never mentions now read "not stated" instead of going to manual review

  1. The AI asks; a person decides.

  2. Each is a Gherkin file in features/; drafts don't count until signed off. See one.

  3. Signing flips the Gherkin file's tag to approved and records its SHA-256. The AI is blocked from signing off or editing signed-off files.

  4. AI answers are recorded and replayed.

    Four pool rules are proved in Lean (lean/Invariants/), such as balances rolling forward; the Python is tested against them. See one.

  5. Catches errors, leaked passwords and confidential names.

  6. It sees only the code and requirements. Findings get fixed with tests.

  7. On a clean machine: every approved Gherkin scenario runs and every Lean proof rebuilds.

  8. The AI merges its own changes; a script confirms it's the right one.

  9. Nightly, the code is deliberately broken to check the tests notice.

The order every change follows. Tap for details.

Nine stages, each with a check.

The product

Public CMBS filings in. Cited surveillance out.

Takes in

Each deal's monthly SEC filings: the loan tape (ABS-EE: every loan's balance, payment status, DSCR, value, servicer codes) and the distribution report (10-D: the special servicer's comments).

Does

Loads each month as filed, so any past date can be replayed. Checks the tape against the report. Reads servicer comments with an AI model; unsure answers go to a person. Flags breaks and changes.

Gives out

Which loans are with the special servicer, each loan's facts and history, alerts, and a one-page committee brief. Every number cites its filing. Through a dashboard, a command line and three Claude skills.

Running on: BANK 2018-BNK13, eight years of monthly filings, and 109 more deals for research.

Why it matters

AI code looks right even when it is wrong.

  • The risk: a silently wrong number is worse than a crash.
  • The stance: assume the AI errs; a person or an automatic check checks it.
  • The numbers are checked too: scheduled balances must roll forward, and the 10-D's delinquent loans and the servicer's transfer date must match the tape. A break raises a flag.

Determinism

Telling an AI what to build. Then making it repeatable, and provable.

  1. 1. Natural language

    How we usually tell a coding agent what we want.

    But: not deterministic. The same words can give different code.

  2. 2. A markdown spec

    Intent written down, the same every time.

    But: a document cannot check the code.

  3. 3. Gherkin feature files Write Sign-off Checks

    Plain-English scenarios with real numbers. One file does two jobs: intent while writing the software, a test while verifying it. Same file, so they never drift apart. Mature tooling in many languages.

    features/surfaces/loss_facts.feature, one of 156 scenarios

    Scenario: What the filings do not give stays
          "not in the data"
  When "pat" asks "What is the ASER of loan 2?"
  Then the answer says the panel does not
       contain that information
  And no figure is estimated

    But: a finite set of examples. High-stakes rules need every case covered.

  4. only for high-stakes rules

  5. 4. Lean 4 proofs Build Final checks

    A theorem holds for every possible input. No separate verification step: the Lean compiler checks the proof, and CI rebuilds it on every change.

    lean/Invariants/Theorems.lean, one of 4 core pool rules

    theorem balance_rollforward :
    (∀ (b s u o e : Int) (loss : Option Int),
      (loss = none ∨ loss = some 0) →
      let m : Month :=
        ⟨some b, some s, some u, some o, loss, some e⟩
      ((roll m).status = .passed ↔ b - s - u - o = e) ∧ …

    In words: a month passes exactly when beginning − scheduled − unscheduled − other principal = ending.

Claude skills

Skills: reusable playbooks for the AI.

  • While building: a questioning skill ran the design debate; the AI vendor's skill reviewed the model calls.
  • At run time: analysts type /cmbs-refresh to pull new filings, /cmbs-ask to ask about a loan or a deal's loans, or /cmbs-brief for a committee brief; answers cite the SEC filing.
  • The limit: each is pre-approved to run only the app's commands; anything else needs the user's OK.
  • Tested under pressure: a practitioner agent briefed committee twice; the second run closed every first-run gap.
