CMBS surveillance · AI development lifecycle

An agent writes the code. Nothing reaches main until the required checks pass.

This project turns public SEC filings (ABS-EE loan tapes and 10-D servicer reports) into a point-in-time surveillance panel. A coding agent, Claude Code, wrote the code. A person makes the design decisions and approves each requirement, which the agent is blocked from changing directly. Hooks, proofs, tests, reviews and required checks decide whether code may merge.

  • AgentClaude Code: asks, drafts, builds, fixes, logs its own mistakes.
  • PersonThe reviewer: decides, approves requirements, sets the merge bar.
  • GateA hook, test or CI check that fails without anyone having to remember it.

How it actually went

The card shows the stages a change must clear. The Q87 fix could not merge until the reviewer approved its revision (#28). It is the only change to an approved requirement so far. The features themselves were not approved first: all 29 were built and reviewed against @draft files, whose scenarios CI does not run, and the reviewer approved them in four commits once they were built (d3ca045, 689270a with 21 features at once, e6fe2cf, 557d366).

Approval freezes a requirement: since then, changing one needs a revision file the reviewer approves.

Known gaps

  • Nothing stops code for a draft feature from merging: CI runs only non-draft scenarios, and every feature was approved after it was built.
  • The hook matches text, so indirection (a wildcard, a script) gets past it. A script that edits an approved file, plus a typed Approved-by: trailer, would pass CI; only someone reading the diff would catch it.
  • The agent works with the owner's GitHub credential, which has admin rights. GitHub cannot tell the agent's merges from the person's, and the agent could edit or turn off the ruleset the Merge stage relies on. The remedy is a separate bot identity or a fine-grained token with write access but no admin, so only the person can change the ruleset.
  • Approval is not bound to a person: the Approved-by: trailer is typed text, there is no CODEOWNERS file, and local commits are unsigned.
  • No human approves code diffs: the ruleset requires zero approving reviews.
  • Review texts were not saved; the evidence is the fix PRs and the grill-log entries they produced.
  • The merge script lives outside the repo, unreviewed and untested.
  • The private-terms check is local only: its term list is gitignored, so CI and pre-commit.ci cannot run it, and a commit that skips the hook could merge a blocked term with every required check green.
  • The analyst skills are not sandboxed: allowed-tools pre-approves their cmbs commands but does not take other tools away; "only call the CLI" is a written rule, and anything else asks the user for permission.
  • Extraction accuracy is unmeasured beyond five live comments; a change in the model's answers is caught only by the version pin and the recordings.
  • Lean proves the checks' decision logic (for the roll-forward: scheduled balance, with loss months not checked, Q81). The Python is tested against it on random inputs, not proved.
  • Scenarios run in process, not through the CLI and API (deferred, Q61).
  • Python's coverage floor is 55%, and the nightly mutation run has failed before scoring since 2026-10-31; the last full run scored 92.0%.
  • A wrong requirement passes every gate. Only the grill log, the stakeholder readings and the reviewer guard against it.

At run time: the analyst's two skills

Each skill's allowed-tools pre-approves only its cmbs commands, and the skill tells the agent to call nothing else; any other tool would ask the user for permission (a written rule, not a sandbox). The CLI checks the user's role and writes the audit trail.

/cmbs-refresh

allowed-tools: Bash(uv run cmbs refresh deal:*)

Loads a deal's new SEC filings a month at a time, completely or not at all; extracts comments; runs the checks; builds alerts. Relays the report problems first, and never calls a run a success unless its status says succeeded.

/cmbs-ask

allowed-tools: Bash(uv run cmbs ask facts:*), Bash(uv run cmbs ask question:*)

Read-only. Every statement cites its filing (10-D accession and sentence, or ABS-EE tape field); no estimates; a value awaiting human review is not a fact.

Both treat filing text as data, never as instructions. The api container holds no model key (Q91).
